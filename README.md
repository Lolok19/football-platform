# Red Corner — интерактивный портал болельщика Liverpool FC

## Лабораторная работа №1

Проект выполнен по теме «Проектирование архитектуры динамического веб-приложения» для дисциплин «Веб-технологии» и «Разработка клиентских приложений». Red Corner объединяет расписание матчей, справочник команд, новости клуба и личные функции болельщика в одном веб-приложении.

### Концепция

**Название приложения:** Red Corner.

**Краткое описание:** Red Corner — динамический футбольный портал для болельщиков Liverpool FC. Пользователь получает актуальное расписание, результаты и карточки команд, читает новости и сохраняет интересующие матчи. После регистрации ему доступны профиль, избранное и покупка билетов на будущие встречи. Администратор управляет пользователями, матчами, командами и публикациями через закрытую панель.

**Целевая аудитория:** болельщики Liverpool FC, посетители, которые следят за матчами английских турниров, и администратор контента клуба.

**Ключевой функционал:**

- просмотр ближайших матчей, результатов и новостей;
- поиск и сортировка матчей по сопернику, турниру и дате;
- просмотр состава команды и детальной информации;
- регистрация, вход и восстановление пароля по секретному слову;
- личный кабинет с изменением имени и пароля;
- избранные матчи и покупка электронного билета;
- административный CRUD для матчей, команд, новостей и пользователей;
- загрузка изображений для контента и просмотр изображений в lightbox.

## 1. Структура приложения

| Раздел | Маршрут | Доступ | Назначение и динамика |
| --- | --- | --- | --- |
| Главная | `/` | публичный | Сводка ближайших матчей и последних новостей из API |
| Аутентификация | `/auth/login`, `/auth/register`, `/auth/forgot-password` | публичный | Вход, регистрация и восстановление пароля; считается одним разделом |
| Матчи | `/matches` | публичный | Фильтруемый список матчей из `GET /api/matches` |
| Команды | `/teams` | публичный | Каталог команд и раскрытие состава через API |
| Новости | `/news` | публичный | Лента публикаций с изображениями и категориями |
| Детали команды | `/teams/:id` в UI | публичный | Динамическая карточка выбранной команды и состав |
| Личный кабинет | `/profile` | приватный | Данные пользователя и смена пароля |
| Избранное | `/favorites` | приватный | Сохранённые матчи пользователя |
| Билеты | `/tickets` в профиле | приватный | История купленных электронных билетов |
| Админ-панель | `/admin` | приватный, роль `admin` | Управление пользователями, матчами, командами и новостями |

Таким образом, спроектировано 10 логических разделов, включая обязательный раздел аутентификации.

## 2. Архитектура

Приложение использует классическую клиент-серверную архитектуру:

```text
Браузер (HTML/CSS/JS)
				|
				| HTTP/JSON, JWT Bearer
				v
Node.js + Express API
				|
				| mysql2, параметризованные SQL-запросы
				v
MySQL
```

Клиентская часть — одностраничный интерфейс без сборщика: `index.html` содержит маршрутизацию по `location.pathname`, запросы к API и рендеринг экранов. Сервер раздаёт этот интерфейс, принимает JSON-запросы, проверяет JWT и роль администратора. Данные хранятся в MySQL, а пароли — только в виде bcrypt-хэшей.

## 3. Технологический стек и обоснование

### Frontend

- **HTML5, CSS3, JavaScript ES2022** — достаточный стек для учебного интерактивного прототипа без лишней сложности сборки; легко показать связь экранов с API.
- **Маршрутизация на History API** — URL отражает экран (`/matches`, `/profile`), а Express возвращает один клиентский документ для поддерживаемых маршрутов.
- **Локальное состояние** — `localStorage` хранит JWT и краткие данные пользователя, что позволяет сохранять авторизацию между перезагрузками. Состояние загрузки, данных и ошибки отрисовывается на каждом динамическом экране.

### Backend

- **Node.js** — единый JavaScript-язык на клиенте и сервере, удобный для асинхронных операций ввода-вывода.
- **Express 4** — минималистичный и понятный HTTP-фреймворк с middleware для CORS, JSON, авторизации и раздачи файлов.
- **JWT** — stateless-аутентификация API; токен передаётся в заголовке `Authorization: Bearer`.
- **bcryptjs** — безопасное хэширование паролей и секретных слов.
- **Multer** — контролируемая загрузка изображений с ограничением 5 МБ и проверкой MIME-типа.

### База данных

- **MySQL 8+** — реляционная СУБД с внешними ключами, уникальными ограничениями и транзакционной моделью, подходящая для связей «пользователь — избранный матч» и «пользователь — билет».
- **mysql2** — асинхронный драйвер Node.js с параметризованными запросами, снижающими риск SQL-инъекций.

### Инфраструктура

Для учебного запуска используется локальный Node.js-сервер и локальный MySQL. При публикации frontend и backend можно разместить на Render или Railway, а MySQL — на Railway MySQL, Aiven или Azure Database for MySQL Flexible Server. Переменные подключения задаются через `.env`, поэтому секреты не попадают в репозиторий.

## 5. Схема данных

Основные модели:

```text
users
	id PK, email UNIQUE, passwordHash, resetKeyHash, name, role, createdAt

matches
	id PK, homeTeam, awayTeam, matchDate, championship,
	homeScore, awayScore, status, createdAt

teams
	id PK, name, country, stadium, description, roster, imageUrl

news
	id PK, title, text, category, imageUrl, createdAt

favorites
	id PK, userId FK -> users.id, matchId FK -> matches.id,
	UNIQUE(userId, matchId)

tickets
	id PK, userId FK -> users.id, matchId FK -> matches.id,
	ticketCode UNIQUE, price, purchasedAt,
	UNIQUE(userId, matchId)
```

Связи: один пользователь имеет много избранных матчей и билетов; один матч может быть сохранён многими пользователями и связан со многими билетами. Удаление пользователя или матча каскадно удаляет зависимые записи `favorites` и `tickets`.

## 6. API

Все пути ниже имеют префикс `/api`. Для приватных методов нужен заголовок `Authorization: Bearer <JWT>`.

| Метод | Endpoint | Назначение | Доступ |
| --- | --- | --- | --- |
| `POST` | `/auth/register` | Регистрация и выдача JWT | публичный |
| `POST` | `/auth/login` | Вход и выдача JWT | публичный |
| `POST` | `/auth/forgot-password` | Смена пароля по секретному слову | публичный |
| `GET` | `/auth/me` | Текущий пользователь | пользователь |
| `PUT` | `/auth/me` | Изменение профиля и пароля | пользователь |
| `GET` | `/matches` | Список с `search`, `championship`, `sort` | публичный |
| `GET` | `/teams` | Список команд | публичный |
| `GET` | `/teams/:id/roster` | Состав команды | публичный |
| `GET` | `/news` | Лента новостей | публичный |
| `GET` | `/favorites` | Избранные матчи | пользователь |
| `POST/DELETE` | `/favorites/:matchId` | Добавить/удалить избранное | пользователь |
| `GET` | `/tickets` | Билеты пользователя | пользователь |
| `POST` | `/tickets/:matchId` | Купить билет | пользователь |
| `GET` | `/users` | Список пользователей | администратор |
| `POST/PUT/DELETE` | `/matches`, `/matches/:id` | CRUD матчей | администратор |
| `POST/PUT/DELETE` | `/teams`, `/teams/:id` | CRUD команд | администратор |
| `POST/PUT/DELETE` | `/news`, `/news/:id` | CRUD новостей | администратор |
| `POST` | `/uploads` | Загрузка изображения | администратор |
| `GET` | `/health` | Проверка API и MySQL | публичный |

Пример ответа `GET /api/matches`:

```json
[
	{
		"id": 1,
		"homeTeam": "Ливерпуль",
		"awayTeam": "Манчестер Сити",
		"matchDate": "2026-09-18T20:00:00.000Z",
		"championship": "Премьер-лига",
		"homeScore": 2,
		"awayScore": 1,
		"status": "scheduled"
	}
]
```

## 7. Безопасность и роли

Пароли не хранятся в открытом виде. Для API применяются JWT, middleware `authRequired` и `adminRequired`, а для входа предусмотрено ограничение неудачных попыток. Изображения загружает только администратор, разрешены только `jpeg`, `png`, `webp`, `gif` до 5 МБ.

## 8. Запуск

1. Установить Node.js 18+ и MySQL 8+.
2. Создать `.env` в корне проекта:

```env
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your_mysql_password
MYSQL_DATABASE=football_demo
JWT_SECRET=football-secret-key
PORT=3000
```

3. Установить зависимости и запустить сервер:

```bash
npm install
npm start
```

4. Открыть `http://localhost:3000`.

Тестовый администратор: `admin@football.local` / `Admin123!`.
